# Think2Go 基准上的评测（GNPR-SID / Foursquare-NYC）

**问题**：把我们的训练免费方法放到 Think2Go（KDD'26, arXiv 2607.28997）的数据集与指标上，与论文中的方法及基线比较。

**结论先说**：我们在这份基准上**明显低于 Think2Go（Acc@1 0.214 vs 0.385）**。Acc@1 略低于 STAN（0.2231），但 Acc@5 0.497 / Acc@10 0.585 / MRR 0.331 介于 STAN 与 GETNext 之间——总体是经典训练序列模型的水平。
这与在 RALLM-POI 数据上的结论相反，说明**方法排名强烈依赖基准**，不是我们前面的计算有问题。

---

## 1. 复现的到底是什么

| 项目 | 内容 |
|---|---|
| 数据来源 | Think2Go 论文指向的 [GNPR-SID](https://github.com/wds1996/GNPR-SID) 仓库，`V1/datasets/nyc/` |
| 文件 | `llm_train.json`（3,305 条）、`llm_val.json`、`llm_test.json`（1,447 条） |
| 输入格式 | `"User_1 checkin history: <ts> visited <a_57><b_31><c_9>, ... When <ts> user_1 is likely to visit:"` |
| 输出 | 目标 POI 的 SID（如 `<a_57><b_31><c_9>`） |
| 测试集 | 1,447 条样本 / 436 用户（多数用户有 2–5 个测试点） |
| 缺失字段 | **无经纬度、无类别**（仓库只发 SID 文本） |

**因此我们的方法只能跑一半**：时序转移与用户画像两条路由可用；地理邻域、类别—时段两条路由**无法计算**。
这不是选择，是数据限制。

## 2. 指标口径

Think2Go 用 `Acc@K` 与 `MRR`，其中

```
Acc@K = (1/|U|) Σ_u |S_u^K ∩ S_u| / |S_u|
```

按**用户**平均，而不是按样本平均。两种口径我都计算了，下面主表用他们论文的口径（按用户）。

## 4. 我们的方法是怎么调的

在校验集上选的组合（不碰 test）：

```
score(v) = 2.0 · P(v | user)                      # 用户长期偏好
         + 1.0 · recency(v, 0.85^k)               # 用户近期访问衰减
         + 1.0 · P(v | last POI)                  # 一阶转移（共现）
```

时段条件化版本在 Acc@1 上略高（0.245），但 Acc@5/10 和按用户的指标更差，因此未采用。

**候选空间覆盖率 94.1%**，即 Acc@10 上限 0.941——我们的 0.585 不是被候选集卡住。

## 5. 为什么差距这么大（与 RALLM 基准对比）

| 维度 | RALLM-POI 基准 | Think2Go 基准 |
|---|---|---|
| 历史长度 | 6 天窗口，约 40 条 | 长历史，平均 43.8 条、跨数月 |
| 预测目标 | 当天最后一次签到 | 整个历史之后的下一次签到 |
| 答案在历史中的比例 | 57% | 76% |
| 计数模型 Acc@1 / HR@1 | 0.53 | 0.21 |
| 我们的相对位置 | 高于 RALLM-POI 与本论文所有基线 | 低于绝大多数基线 |

关键差别不在"重访比例"，而在**上下文可预测性**：RALLM 的样本窗口短、目标与近期行为强相关，计数模型几乎能闭眼命中；
Think2Go 的样本要求从跨越数月的长历史推断下一次访问，需要真正的用户建模——这正是训练模型的价值所在。

---

## 6. 对论文写作的含义

1. **不能声称"训练免费方法普遍优于训练模型"**——在 Think2Go 基准上不成立。
2. **可以说"在 LLM4POI 风格的短窗口 next-POI 基准上，训练免费的时序检索已达到甚至超过现有 LLM 方法"**，并给出该基准的条件。
3. 若要把 Think2Go 纳入对比表，必须同时注明：我们缺少地理/类别特征（数据未发布），且未使用任何训练。
4. 这一组结果本身是一个有价值的发现：**同一位方法在两个主流基准上的排名完全相反**，说明
   当前 next-POI 评测的可比性存在问题（数据版本、切分方式、目标定义三者都不统一）。
